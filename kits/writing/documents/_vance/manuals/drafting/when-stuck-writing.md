# When Stuck Writing — drafting-specific stuck patterns

Different from generic `stuck` from basic. Writing-stuck has
its own textures: you can be moving but stuck on the wrong
problem, or paralysed by the gap between what you imagined
and what's on the page.

This manual maps the textures and the moves.

## Pattern 1 — perfectionism mid-sentence

Symptom: the user types six words, deletes them, types four,
deletes those, types nothing for a minute. Cursor blinks.

Cause: the user is comparing each emerging sentence to the
imagined-final-sentence. Comparison loses every time.

Move: lower the bar explicitly. "Write the worst version of
this sentence. We'll fix it later." If the user complies,
words appear. If they can't bring themselves to write
something bad, the perfectionism is deeper — see Pattern 6.

## Pattern 2 — topic drift

Symptom: the user has written 800 words; the last 400 are
about a tangentially-related topic. They're writing
fluently but on the wrong topic.

Cause: writing surfaces interesting threads. The mind
follows the most-interesting one, even if it's not the
assigned one.

Move:

- **Mark the drift.** Surface it: "You started writing
  about A; the last few paragraphs are on B. Was that
  intentional?"
- **If intentional:** the topic shifted; let it. Often a
  better piece. Update the one-line summary; continue.
- **If unintentional:** mark where the drift starts.
  Cut from there; resume on topic. The drift-text might
  become its own piece later — save it.

## Pattern 3 — length dread

Symptom: the user knows the piece needs to be ~2000 words.
They have 200 words. They keep recalculating ("1800 to
go") and feeling worse.

Cause: word-count panic invokes the imagined-finished
piece, which is overwhelming.

Move:

- **Stop counting.** Hide the word counter. Aim for the
  time-box, not the count.
- **Decompose.** "How many sections does this have?"
  6 sections × 300 words each is more tractable than
  "2000 words". Now the goal is "next 300 words"; that
  fits in a 25-minute box.
- **Scope down.** Maybe it's a 1200-word piece, not 2000.
  Length should serve the content, not the other way.

## Pattern 4 — the gap between vision and page

Symptom: the user wrote a paragraph. They reread it. It's
nothing like what they imagined. Frustration; rewriting
in place.

Cause: imagination has high resolution and no friction.
Page has low resolution and lots of friction. The first
draft is *always* less than imagined.

Move:

- **Surface the gap explicitly.** "You imagined something;
  the page has something less. That's universal — every
  draft is the worst version of the piece."
- **Promote the imagined.** "What did you imagine? Tell me
  what's missing." Sometimes the gap names a real
  inadequacy; sometimes it names an unrealistic
  expectation.
- **Move on.** Editing fills the gap progressively; the
  first draft can never close it.

## Pattern 5 — too many tabs

Symptom: the user is "researching" — 12 tabs open, jumping
between sources, no words typed in 20 minutes.

Cause: drafting is hard; researching feels productive.
The user is avoiding the hard work behind the appearance
of preparation.

Move:

- **Close the tabs.** Literally. Bookmark / save them; off
  the screen. Open one if needed; close it after.
- **Set a write-only window.** No tabs allowed during the
  draft.
- **Permit research afterwards.** Use placeholders during
  draft (`[FACT TK]`, `[CITATION TK]`); look up in the
  post-draft pass.

If the user genuinely needs the research before writing
makes sense (e.g. an unfamiliar domain), that's a different
phase — separate research session, not drafting session.

## Pattern 6 — paralysed-can't-write-anything

Symptom: the user cannot produce a single sentence. Even
"terrible first draft" doesn't unblock.

Causes (more than one usually applies):

- **Stakes too high.** Important piece, important reader,
  career-relevant.
- **Identity threat.** "If I can't write this well, I'm
  not a writer."
- **Wrong assignment.** They've been told to write
  something they don't want to write.
- **Tired.** Cognitive depletion; the writing-self is
  asleep.
- **The thing isn't ready to be written.** They haven't
  thought it through enough; writing is premature.

Move:

- **Surface the cause.** "What's making this hard?" The
  user often knows; the naming reduces stakes.
- **For high-stakes:** lower the audience. "Forget the
  real audience; write this for me, in chat. We'll fix
  the audience later." Sometimes shifts the stakes
  enough to unblock.
- **For tired:** stop. Schedule another session. Tired-
  drafting produces text the user has to throw out
  anyway.
- **For not-ready:** suggest a different mode (`re-frame`
  from basic, or `rubber-duck`). Drafting won't help
  until the thinking is further along.

## Pattern 7 — comparison-spiral

Symptom: the user starts reading published work, gets
discouraged, returns to their draft feeling worse.

Cause: published work has been edited by professionals.
First drafts are not for comparison.

Move: ban examples during drafting. They're useful for
`tone-and-voice` later, when the structure is settled.
Right now they're poison.

If the user genuinely needs a structural model (e.g.
"how does an essay open?"), pick *one* example, take a
specific structural lesson, close it. Don't browse.

## Pattern 8 — over-explaining

Symptom: the user keeps adding qualifications, footnotes,
parentheticals. Each sentence sprouts three.

Cause: anxiety about being misunderstood. Each
clarification is reassurance.

Move:

- **Defer.** "All this clarification can be added in the
  edit pass — in the draft, write the unqualified
  version. We'll see what actually needs qualifying."
- **Most of the qualifications are unnecessary.** First-
  draft prose tends to over-hedge; editing trims.

## Anti-patterns

### Treating writing-stuck as motivation problem

"Just push through!" — almost never works. The block is
mechanical, not motivational. Find the specific texture.

### Adding more pressure

Deadline reminders, audience-stake reminders, importance
reminders. All make the block worse. Lower the stakes,
don't raise them.

### Skipping diagnosis

Going straight to "try terrible first draft". Sometimes
right; often the wrong technique for *this* texture. Map
the pattern first.

### Lecturing about the writing process

"Many great writers also struggle." True; not useful. The
user is paralysed and tired of pep talks. Be useful
instead.
