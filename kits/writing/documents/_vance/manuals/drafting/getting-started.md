# Getting Started — moves to break the blank page

The page is empty. The user is staring at it. The hardest
sentence in any draft is the first one. The trick is to
stop trying to write *the* first sentence and write *a*
first sentence — knowing it'll be replaced.

## Five moves to pick from

### 1. Talk it, then type it

The user explains what they want to write to someone (real
or imaginary) for two minutes, out loud. Then they write
down what they said.

Why it works: the talking-self is fluent; the writing-self
is paralysed. Bypass the writing-self.

Variant: voice-record on a phone, transcribe later. Useful
for users whose typing-self is the bottleneck.

When the user is in a chat with the model: the model can
*be* the listener. Ask: "Tell me what you want to write.
Don't structure it. I'll just listen and then we'll
capture what you said."

### 2. Terrible first draft

Permission to write something *bad*. The instruction is
explicit: "Write the worst version of this. Use clichés,
contradict yourself, leave gaps."

Why it works: perfectionism shows up at the standard
"first draft" frame. Lowering the bar to "terrible"
shifts the goal from quality to production.

The user almost always produces something usable, because
"terrible" is impossible to hit deliberately.

### 3. Write the middle first

Skip the introduction; skip the conclusion. Start with the
section the user has the most thoughts on right now.

Why it works: openings and closings are *recap-of-the-
whole*; you can't write them well before the whole
exists. Middles are local-content; tractable.

Once a few middle paragraphs exist, the introduction
"writes itself" because the user knows what they're
introducing.

### 4. Question and answer

The user lists 5-10 questions about their topic. Then
answers each one in one paragraph. The draft is the
answers (lightly edited).

Why it works: questions are easier to generate than
arguments. Answers are easier to write than essays.

Especially good for non-fiction: explainers, how-tos,
analytical pieces.

### 5. Email to a friend

The user pretends to write the piece as an email to a
specific friend. They explain it informally, with the
tone they'd use in chat.

Why it works: email has lower stakes than "publication";
voice loosens; structure follows naturally because emails
have an implicit "what you need to know" arc.

Most of the email survives into the draft after a register
pass.

## Picking which move

| User says | Try |
|---|---|
| "I don't know where to start." | Write-the-middle |
| "What I want to say is too big." | Question-and-answer |
| "Everything I write sounds wrong." | Terrible-first-draft |
| "I can talk about it but can't write it." | Talk-it-then-type |
| "It's too formal in my head." | Email-to-a-friend |

If unsure: terrible-first-draft. It's the most universal.

## What to NOT do at this stage

- **Outline first.** For some users, outlining unblocks;
  for many, outlining is procrastination disguised as
  preparation. If the user has been outlining for 30
  minutes and not writing, the outline is the block.
- **Research more.** Same trap. "I need to know more
  before I can write" is sometimes true; usually it's
  avoidance. Try to draft with what you know; let gaps
  drive specific research.
- **Re-read what you wrote.** During drafting, no
  rereading. The earlier sentence is good enough; the
  next sentence is the work.
- **Choose the perfect tone.** Tone is fixable in
  `tone-and-voice`. Drafting tone is "whatever comes
  out".

## When the move doesn't land

After ~5 minutes of trying a move and still not writing:

- Switch to a different move from the menu.
- Sometimes the user isn't blocked — they're tired. "Try
  again tomorrow" is a valid output.
- Sometimes the assignment itself is wrong (they don't
  actually need to write this). That's `re-frame` from
  basic/stuck.

Don't pile on technique. Two failed moves means rethink the
session, not try a third move.

## Output line

- "**Move:** ⟨specific⟩. **Goal:** ⟨n⟩ words / one
  paragraph / answer ⟨specific question⟩."
- "**Switch move** — ⟨first move⟩ didn't land. Try
  ⟨second⟩."
- "**Not a drafting block** — see ⟨re-frame from stuck /
  the user is tired⟩."
