# Re-frame — when the question itself is the problem

Stuck because the question is wrong. Symptoms:

- Every option you generate feels suboptimal.
- You can solve the problem locally but it doesn't change anything
  important.
- You keep arguing with yourself about the same trade-off.
- You start the work, then drift to other things, then come back
  reluctantly.

These are signals that the framing is broken, not that you're
incompetent. Re-frame upward.

## Probe questions

Ask the user one or two of these — not all. Pick what fits.

- **"What problem is this supposed to solve?"** — get the actual
  goal one level above what they asked.
- **"What changes if you don't decide this?"** — sometimes the
  decision is fake; doing nothing is fine.
- **"Whose question is this?"** — borrowed problems are the worst
  kind to be stuck on.
- **"What would have to be true for option A to be obviously
  right?"** — surfaces hidden criteria.
- **"If you couldn't do any of A/B/C, what would you do?"** —
  forces the user out of the trap they've narrowed themselves
  into.

## Common re-frames that work

- **"How do I do X?"** → **"Should I do X?"**
- **"Which tool is best for Y?"** → **"Do I actually need Y?"**
- **"How to convince Z?"** → **"Why does Z disagree?"**
- **"How to fix the thing?"** → **"Why does the thing keep
  breaking?"**
- **"Plan the next month"** → **"What does the next month need to
  produce?"**

The pattern: trade *how* for *whether*, *which* for *why*. The
upward direction almost always gives more leverage.

## When re-framing makes things worse

- The user is on a deadline. Re-framing now is escapism. Help them
  finish the local task; re-frame in retrospect.
- The user has already re-framed three times in the same session.
  They're spinning. Force a commit ("pick the version of the
  question you'll work on for an hour, then revisit").
- The re-frame moves into existential territory ("am I doing the
  right job", "should I be in this relationship") when the
  original question was small. That's *too* upward — the user
  needs the small task back.

## Output line

End with one of:

- "**Try this re-frame:** ⟨new question⟩."
- "**The original question is fine** — you're stuck on technique,
  not framing. See `narrow-scope` or `switch-modality`."
- "**This goes deeper than this session.** Park it; tackle the
  small, executable next step now."
