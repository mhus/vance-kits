# Switch modality — when the medium is fighting the user

Stuck because the user has been working in one channel for too
long and the channel is now the bottleneck. Symptoms:

- Re-reading the same paragraph for the third time.
- Typing and deleting the same sentence.
- Eyes glazed; can't tell if the code is right or wrong anymore.
- Words feel slippery — can't pin down what you mean.

Different problems want different mediums. Switching breaks the
groove.

## The modality grid

| From | Try | When it works |
|---|---|---|
| Text | Talking aloud | When you can't articulate the thought to yourself |
| Reading | Writing | When the input volume is too high to absorb passively |
| Code | Whiteboard | When the structure is fighting the editor |
| Solo | One other person | When the loop is too tight to escape internally |
| Screen | Walking | When the body has gone still and so has the head |
| Detail | Outline | When you've been zoomed in for an hour |
| Outline | Detail | When the high-level keeps getting agreed to but nothing ships |
| Reading guides | Trying it | When you've been in research mode too long |
| Trying it | Reading guides | When you've been in flailing mode too long |

## Specific moves

- **Read it aloud.** Reads differently in the ear than on the
  page. Especially writing.
- **Explain to a non-expert.** The forced compression surfaces
  the thing you don't actually understand. (See `rubber-duck`.)
- **Sketch it.** Even badly. The ten-second sketch on paper
  reveals what the elaborate diagram tool was hiding.
- **Print it.** Reads with different attention on paper. Marks
  up differently. Catches things on-screen review missed.
- **Walk for fifteen minutes, no phone.** Not "go for a walk
  forever". Fifteen minutes, then come back to the work.
- **Sleep on it.** Cheap and reliable. Most decisions made at
  11pm look different at 7am.

## When NOT to switch

- The user has switched three times already in the session. They
  are avoiding the work. Force a commit (`narrow-scope`).
- The user is on a tight deadline. Switching costs context;
  fifteen minutes is fifteen minutes. Sometimes the move is
  push-through with weaker tools, not switch.
- The thing is genuinely hard at the level it's at, and the
  user just needs to slog. Switching is sometimes
  procrastination wearing a productivity costume.

## How to suggest a switch

Concrete. Short. Specific time.

- "Stop the doc. Talk to me about it for two minutes."
- "Whiteboard the flow. Photo it. Come back."
- "Walk for ten minutes. No agenda."

Not: "maybe try a different approach". That's nothing.

## Output line

End with one of:

- "**Switch:** ⟨specific medium and duration⟩."
- "**Don't switch yet.** You haven't bottomed out the current
  channel. Try ⟨move⟩ first."
- "**You've switched enough.** Commit to a slice and stop the
  ceremony — see `narrow-scope`."
