The user is taking notes — from reading, from research,
from thinking — and wants them to be useful later. The
hardest test of a note-taking system isn't capture
(everyone captures); it's *retrieval and reuse* months
later. A note you can't find or don't understand later
might as well not exist.

The skill emphasises: atomic notes, clear language,
explicit linking, and progressive distillation rather
than perfect first-pass capture.

## Default protocol

1. **Why are you taking notes?** Different goals warrant
   different methods. Research project (will write this
   up); personal learning (want to remember); curiosity
   browsing (low retention OK). The why drives the
   technique.
2. **One concept per note.** A note that mixes three
   ideas can't be linked, recalled, or reused
   precisely. See `zettelkasten-basics`.
3. **Write notes for future-you, not present-you.**
   Present-you remembers context. Future-you has
   forgotten. Notes need enough context to be
   self-contained.
4. **Layer the abstraction.** Capture verbatim ⇒
   summary ⇒ key insight. Each layer is a different
   density. See `progressive-summarisation`.
5. **Add retrieval cues.** What words / questions / tags
   would future-you search for to find this? See
   `retrieval-cues`.

## On-demand manuals

- `zettelkasten-basics` — atomic notes, linking, no
  rigid hierarchy. The Niklas Luhmann pattern adapted to
  current tools. When linking pays off; when it doesn't.
- `progressive-summarisation` — Tiago Forte's layered
  approach. Capture ⇒ bold ⇒ highlight ⇒ summary.
  When to stop layering. How to avoid the
  highlighting-everything trap.
- `retrieval-cues` — making notes findable later. Tags,
  keywords, search-friendly titles, the "if I were
  looking for this in 6 months..." mental test.

If you're new to note-taking, start with
`zettelkasten-basics` — atomic notes are the foundation.

## Hard rules

- **A note you can't find isn't a note.** Capturing
  without retrieval is hoarding. Test retrievability;
  fix what fails.
- **Don't take notes you won't use.** Some material
  doesn't need notes. The book you read once for
  pleasure doesn't need a Zettelkasten entry. Match
  effort to expected value.
- **Don't copy verbatim and call it a note.** The act of
  *processing* the material is what makes the note
  useful. Pure copying is highlighting in disguise.
- **Don't fall for the system.** Note-taking-as-hobby
  produces beautiful infrastructure and few notes worth
  reading. The notes are the point; the system serves
  the notes.
- **Don't link compulsively.** Links work when they're
  meaningful. A note linked to 50 things is a note in a
  broken graph.
- **Don't distinguish "important" notes from "background"
  notes by formatting.** Most "important" notes turn out
  to be ordinary later; most "background" notes are the
  gold. Treat them equivalently; let importance emerge.
